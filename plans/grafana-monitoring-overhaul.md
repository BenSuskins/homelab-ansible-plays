# Grafana & Monitoring Overhaul Plan

> Implementation note: work on a branch and open a PR — pushes to `main` auto-deploy fleet-wide via `.github/workflows/update.yml`. Commit this plan file with the change.

## Context

Audit of the Grafana setup in `homelab-ansible-plays` found a working but gappy observability stack:

- **7 dashboards** in a flat General folder: 5 hand-made (`homelab-overview`, `docker-containers`, `logs`, `proxmox`, `pubgolf-backend`), 2 imported (`traefik` gnetId 17346, `truenas`).
- **`proxmox.json` is dead** — all 8 panels query `pve_*` metrics but no `prometheus-pve-exporter` exists anywhere. The hypervisor is unmonitored.
- **Alert rules never load** — `config/prometheus/config.yml.j2` declares `rule_files: ["alerts.rule.yml"]` but `tasks/docker/prometheus.yml` copies the file as `alert.rules.yml`. No Alertmanager, no Grafana alerting → even fixed, rules route nowhere.
- **Metrics scraped but never visualized**: Tailscale (202:9002), Prometheus self-metrics. **Not scraped at all**: Alloy, Loki, Gatus, Grafana. family-hub's Spring Boot metrics are commented out.
- **Hygiene**: Prometheus default 15d retention, Loki unbounded disk growth (no compactor/retention), overview disk panel only watches `/`, truenas dashboard refreshes at 5s vs 60s scrapes, redundant nested Grafana volume mount, no restart-on-config-change for prometheus/loki/alloy, Grafana provisioning generated by a hacky inline `entrypoint` heredoc.

**User decisions**: deploy pve-exporter (PVE API token → vault); Grafana unified alerting **visible in Grafana only, NO Discord/external notifications**; all four new dashboards (monitoring self-health, Tailscale, family-hub, Gatus SLO); all hygiene fixes; reorganize into Grafana folders + improved home dashboard.

## Phase 1 — Metrics pipeline plumbing

### 1.1 Rewrite `config/prometheus/config.yml.j2`

Requirements: drop dead `rule_files`; **merge same-name services into one job** (alloy becomes a metrics service on 5 hosts — the current per-service loop would emit 5 duplicate `job_name: "alloy"` blocks = invalid config); add per-target `host` label from `friendly_name`; support `metrics_params` (pve-exporter needs `?target=`). New content:

```jinja
global:
  scrape_interval: 15s

scrape_configs:

{% for name, group in (all_services | selectattr('metrics', 'defined') | selectattr('metrics') | list) | groupby('name') %}
  - job_name: "{{ name }}"
    scrape_interval: 60s
{% if group[0].metrics_path is defined %}
    metrics_path: {{ group[0].metrics_path }}
{% endif %}
{% if group[0].metrics_params is defined %}
    params:
{% for k, v in group[0].metrics_params.items() %}
      {{ k }}: ["{{ v }}"]
{% endfor %}
{% endif %}
    static_configs:
{% for svc in group %}
      - targets: ["{{ svc.ip }}:{{ svc.metrics_port | default(svc.port) }}"]
        labels:
          host: "{{ svc.friendly_name | default('') }}"
{% endfor %}
{% endfor %}

  - job_name: "prometheus"
    scrape_interval: 5s
    static_configs:
      - targets: ["localhost:9090"]
        labels:
          host: "Monitoring"
```

`rules.yml` — `apiVersion: 1`, groups in provisioned folder `Alerts`, `interval: 1m`. Rule skeleton (Grafana 13 file-provisioning schema): instant Prometheus query `A` + `__expr__` threshold `C`:

```yaml
apiVersion: 1
groups:
  - orgId: 1
    name: infrastructure
    folder: Alerts
    interval: 1m
    rules:
      - uid: host-down
        title: Host down (node metrics absent)
        condition: C
        for: 5m
        noDataState: OK
        execErrState: Error
        isPaused: false
        labels: { severity: critical }
        annotations: { summary: "A host stopped reporting node metrics via Alloy remote-write" }
        data:
          - refId: A
            relativeTimeRange: { from: 600, to: 0 }
            datasourceUid: prometheus
            model:
              refId: A
              instant: true
              intervalMs: 1000
              maxDataPoints: 43200
              expr: count by (host) (last_over_time(node_load1[1h])) unless count by (host) (node_load1)
          - refId: C
            datasourceUid: __expr__
            model:
              refId: C
              type: threshold
              expression: A
              conditions:
                - evaluator: { type: gt, params: [0] }
```

All rules (uid | expr for A | threshold C | for):

**Group `infrastructure`:**
| uid | expr | C | for |
|---|---|---|---|
| `host-down` | `count by (host) (last_over_time(node_load1[1h])) unless count by (host) (node_load1)` | gt 0 | 5m |
| `disk-space-low` | `min by (host, mountpoint) (node_filesystem_avail_bytes{fstype=~"ext4\|xfs"} / node_filesystem_size_bytes{fstype=~"ext4\|xfs"})` | lt 0.10 | 15m |
| `disk-fill-predicted-24h` | `predict_linear(node_filesystem_avail_bytes{fstype=~"ext4\|xfs"}[6h], 86400) and (node_filesystem_avail_bytes{fstype=~"ext4\|xfs"} / node_filesystem_size_bytes{fstype=~"ext4\|xfs"} < 0.25)` | lt 0 | 30m |
| `memory-high` | `1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)` | gt 0.90 | 10m |
| `container-restarting` | `changes(container_start_time_seconds{name!=""}[30m])` | gt 3 | 0m |
| `container-oom` | `increase(container_oom_events_total{name!=""}[30m])` | gt 0 | 0m |
| `backup-stale` | `time() - wedding_backup_last_success_timestamp_seconds` | gt 93600 | 0m — **`noDataState: Alerting`** (missing metric = backups never reported) |

Rationale for `host-down`: Alloy remote-writes, so hosts have no `up` series — staleness (present in last 1h, absent now) is the detector. `noDataState: OK` so a fresh Prometheus doesn't fire. `container-restarting` threshold 3 tolerates daily update-play recreations.

**Group `applications`** (migrated pubgolf rules — now `job`-filtered since family-hub emits the same Micrometer names; duplicate the three for `job="family-hub"`):
| uid | expr | C | for |
|---|---|---|---|
| `pubgolf-5xx-rate` | `sum(rate(http_server_requests_seconds_count{job="pubgolf-backend", status=~"5.."}[5m]))` | gt 0.05 | 2m |
| `pubgolf-latency-p95` | `histogram_quantile(0.95, sum by (le) (rate(http_server_requests_seconds_bucket{job="pubgolf-backend"}[5m])))` | gt 1 | 2m |
| `pubgolf-jvm-heap` | `max(jvm_memory_used_bytes{job="pubgolf-backend", area="heap"} / (jvm_memory_max_bytes{job="pubgolf-backend", area="heap"} > 0))` | gt 0.85 | 3m |
| `family-hub-*` | same three with `job="family-hub"` | | |

**Group `monitoring`:**
| uid | expr | C | for |
|---|---|---|---|
| `scrape-target-down` | `min by (job, instance) (up)` | lt 1 | 5m |
| `prometheus-ingest-stalled` | `rate(prometheus_tsdb_head_samples_appended_total[10m])` | lt 1 | 10m |
| `prometheus-compaction-failures` | `increase(prometheus_tsdb_compactions_failed_total[3h])` | gt 0 | 0m |

## Risks / gotchas

- **Grafana 13 alerting schema**: if boot logs show schema errors, build one rule in the UI and export via `GET /api/v1/provisioning/alert-rules/<uid>/export?format=yaml`, then pattern-match. Provisioned rules are read-only in the UI (by design).
- **Duplicate dashboard UIDs during migration**: mitigated by the stray-file cleanup running before copy/restart in `grafana.yml`.
